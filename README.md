# حلاقي — Hallagi
## نظام إدارة محلات الحلاقة الرجالية في المملكة العربية السعودية
### «محلك في يدك»

منصة SaaS متعددة المنشآت لإدارة محلات الحلاقة: نقطة بيع لمسية، فواتير ضريبية متوافقة مع هيئة الزكاة والضريبة،
مواعيد وحجز إلكتروني، مخزون منتجات، برنامج ولاء، خزينة وورديات، وتسويات مالية للحلاقين.

- **الواجهة:** عربية بالكامل مع RTL حقيقي، متجاوبة مع الجوال
- **العملة:** الريال السعودي (`35.00 ر.س`)
- **التقنيات:** ASP.NET Core 10 (Clean Architecture) · Angular 20 · EF Core · SQL Server (أو SQLite للعرض)

## 1. الميزات

| المجال | ما يقدّمه النظام |
|---|---|
| **نقطة البيع** | خدمات ومنتجات في شاشة واحدة، قارئ باركود، كود خصم، خصم يدوي بحد أقصى وصلاحية، استبدال نقاط الولاء، معاينة فورية للضريبة، بيع بالكاشير أو بيع ذاتي للحلاق، مفتاح Idempotency يمنع تكرار البيع |
| **الفاتورة الضريبية (ZATCA)** | «فاتورة ضريبية مبسطة» برمز QR بصيغة TLV/Base64 (المرحلة الأولى)، رقم ضريبي وسجل تجاري، أسعار شاملة أو غير شاملة الضريبة، لقطة لهوية البائع وقت البيع، تقرير الضريبة المحصّلة للإقرار |
| **المواعيد** | جدول يومي لكل حلاق، أوقات متاحة محسوبة من ساعات الفرع ومدة الخدمات، منع التعارض، قائمة انتظار للحضور المباشر، بدء الخدمة ثم التحصيل من نقطة البيع، تذكير واتساب بضغطة |
| **الحجز الإلكتروني** | صفحة عامة `/book/{slug}` بهوية المحل، اختيار الفرع والخدمات والحلاق واليوم والوقت، رقم حجز وإلغاء ذاتي، حد للحجوزات النشطة لكل جوال |
| **المخزون** | منتجات مع تكلفة وهامش، مخزون مستقل لكل فرع، استلام وجرد، سجل حركة لا يُعدّل، تنبيه النفاد، إرجاع تلقائي للمخزون عند إلغاء البيع |
| **الولاء والعروض** | نقاط لكل ريال، قيمة نقطة وحد أدنى للاستبدال، عكس النقاط عند الإلغاء، أكواد خصم (نسبة/مبلغ، حد أدنى، سقف، عدد استخدامات، صلاحية) |
| **المالية** | خزينة وورديات لكل فرع، مصروفات، سجل مالي للحلاقين، سلف، تسليمات نقدية، تسويات بأربع طرق تعويض — **العمولة تُحسب على إيراد الخدمات بدون الضريبة والمنتجات** |
| **SaaS** | خطط اشتراك بحدود، مالك منصة ينشئ المنشآت، هوية بصرية لكل منشأة، أجهزة POS |
| **الأمان** | JWT قصير العمر + Refresh Token دوّار مع كشف إعادة الاستخدام، صلاحيات دقيقة قابلة للتخصيص، عزل كامل بين المنشآت والفروع، حد لمحاولات الدخول، ترويسات أمان، إبطال الجلسات عند تغيير كلمة المرور |

## 2. البنية المعمارية

```
Hallagi/
├── src/
│   ├── Hallagi.Domain/          # الكيانات والتعدادات — بلا أي اعتماديات
│   ├── Hallagi.Application/     # حالات الاستخدام مقسمة حسب المجال
│   │   ├── Common/              #   IAppDbContext, ITokenService, IPasswordHasher, الصلاحيات، الأخطاء
│   │   ├── Sales/ Booking/ Commerce/ Finance/ Treasury/ Expenses/
│   │   ├── Identity/ Organizations/ Catalog/ Reports/
│   │   └── Tax/                 #   محرك التسعير والضريبة + ترميز QR الخاص بـ ZATCA
│   ├── Hallagi.Infrastructure/  # EF Core (إعداد لكل كيان)، الهجرات، البيانات الأولية، JWT، BCrypt
│   └── Hallagi.Api/             # Controllers رفيعة، Middleware، إعداد الاستضافة
├── tests/
│   ├── Hallagi.UnitTests/       # قواعد العمل على SQLite (حسب المجال)
│   └── Hallagi.IntegrationTests/# خط HTTP الكامل عبر WebApplicationFactory
├── hallagi-client/              # Angular 20
│   └── src/app/
│       ├── core/                #   auth, http, state, models, api (عملاء API مطبوعة), pricing
│       ├── shared/              #   ui (مكونات مشتركة، QR), pipes
│       └── features/            #   كل شاشات المنتج
├── docker-compose.yml           # SQL Server + API + Web (nginx)
└── .github/workflows/ci.yml     # بناء + اختبارات + E2E
```

اتجاه الاعتماد: `Api → Infrastructure → Application → Domain`. منطق الأعمال لا يعرف شيئًا عن HTTP أو JWT أو BCrypt.

## 3. التشغيل

### أ) تجربة سريعة بدون SQL Server (SQLite + بيانات عرض)

```bash
# الخادم
ASPNETCORE_ENVIRONMENT=Development Database__Provider=Sqlite \
ConnectionStrings__Default="Data Source=hallagi.db" \
dotnet run --project src/Hallagi.Api --urls http://localhost:5095

# الواجهة
cd hallagi-client && npm ci && npx ng serve --port 4300
```

افتح `http://localhost:4300` — وصفحة الحجز العامة للعرض: `http://localhost:4300/book/elite`

### ب) تطوير مع SQL Server LocalDB

```bash
cd src/Hallagi.Api && dotnet run --launch-profile http     # http://localhost:5095
cd hallagi-client && npm ci && npm start                   # http://localhost:4200
```

في وضع التطوير تُطبَّق الهجرات وتُزرع بيانات عرض واقعية تلقائيًا.

### ج) الإنتاج عبر Docker

```bash
cp .env.example .env        # ضع كلمات مرور وأسرارًا حقيقية
docker compose up -d --build
# http://localhost:8080
```

في الإنتاج: تُطبَّق الهجرات وتُنشأ خطط الاشتراك وحساب مالك المنصة من `ADMIN_EMAIL/ADMIN_PASSWORD` فقط — **لا توجد أي حسابات عرض**.
الخادم يرفض التشغيل بمفتاح JWT ضعيف أو افتراضي، ويكتب سجلات JSON منظّمة، ويوفّر `/health/live` و`/health/ready`.

## 4. حسابات العرض (التطوير فقط)

| الدور | البريد | ماذا يرى |
|---|---|---|
| مالك المنصة | `admin@hallagi.sa` | إنشاء المنشآت والخطط والاشتراكات |
| مالك منشأة | `owner@hallagi.sa` | كل شيء داخل منشأته |
| مدير فرع | `manager@hallagi.sa` | فرعا النرجس والياسمين |
| كاشير | `cashier@hallagi.sa` | البيع، المواعيد، العملاء، الخزينة |
| حلاق | `barber@hallagi.sa` | «ملخصي» وبيع ذاتي ومواعيده |

كلمة المرور الموحدة: `Hallagi@123` · كوبونات العرض: `WELCOME10` و`EID20` · الرقم الضريبي التجريبي `310123456700003` (وهمي).

## 6. قبل الإطلاق

1. **الفوترة الإلكترونية — المرحلة الثانية (الربط):** النظام يغطي المرحلة الأولى (الإصدار + QR). منشآت المرحلة الثانية تحتاج
   تكاملًا مع منصة «فاتورة» (XML UBL، توقيع رقمي، شهادة CSID) — المحرك الحالي مهيأ لذلك عبر لقطة بيانات البائع لكل فاتورة.
2. **الأسرار:** `JWT_KEY` و`DB_PASSWORD` و`ADMIN_PASSWORD` من مخزن أسرار، لا في المستودع.
3. **HTTPS:** ضع موزع حمل/Ingress بشهادة TLS أمام `web` (الخادم يحترم `X-Forwarded-*`).
4. **النسخ الاحتياطي:** جدولة نسخ احتياطي لقاعدة البيانات (`sqldata`).
5. **التذكيرات الآلية:** التذكير الحالي عبر رابط واتساب يدوي؛ للإرسال الآلي اربط مزود SMS/WhatsApp Business API.
