# حلاقي — Hallagi
## نظام إدارة محلات الحلاقة الرجالية في المملكة العربية السعودية
### الشعار: «محلك في يدك»

تطبيق SaaS متعدد المنشآت (Multi-tenant) لإدارة محلات الحلاقة: تسجيل المبيعات بسرعة،
متابعة الخزينة والورديات، إدارة الحلاقين والتعويضات، العملاء، المصروفات، والتقارير.

- **الواجهة:** عربية بالكامل + اتجاه RTL حقيقي (ليس مجرد محاذاة نص)
- **العملة:** الريال السعودي (ر.س) — تُعرض المبالغ بصيغة `35.00 ر.س`
- **التقنيات:** ASP.NET Core (.NET 10) + Angular 20 + SQL Server (EF Core)

## 2. التشغيل السريع (خطوتين)

### الخطوة 1 — تشغيل الخادم (API)

```bash
cd src/Hallagi.Api
dotnet run --launch-profile http
```

عند أول تشغيل في وضع التطوير يقوم الخادم تلقائيًا بـ:
1. إنشاء قاعدة البيانات (`Hallagi`) على `(localdb)\MSSQLLocalDB`.
2. تنفيذ الهجرات (Migrations).
3. زرع بيانات تجريبية واقعية (منشأة، 3 فروع، 6 خدمات، 4 حلاقين، 5 عملاء، مبيعات 8 أيام مصروفات).

سيعمل الخادم على: `http://localhost:5095` (وثائق OpenAPI: `http://localhost:5095/openapi/v1.json`)

### الخطوة 2 — تشغيل الواجهة (Angular)

```bash
cd hallagi-client
npm install
npm start
```

سيعمل التطبيق على: `http://localhost:4200`

## 3. حسابات الدخول

> **لا يوجد تسجيل عام.** كل الحسابات يُنشئها حساب مالك المنصة (الأعلى).
> حسابات العرض التالية للبيئات التجريبية فقط — كلمة مرور موحدة تُغيَّر قبل أي استخدام إنتاجي.

| الدور | البريد الإلكتروني | كلمة المرور | ماذا يفعل |
|---|---|---|---|
| **مالك المنصة** | `admin@hallagi.sa` | `Hallagi@123` | لوحة المنصة: إنشاء المنشآت والفروع، إدارة الخطط والاشتراكات، إعادة تعيين كلمات مرور المالكين |
| **مالك منشأة** | `owner@hallagi.sa` | `Hallagi@123` | كل شيء داخل منشأته: الفروع، المستخدمون، التقارير، المالية |
| مدير فرع | `manager@hallagi.sa` | `Hallagi@123` | فرعا النرجس والياسمين |
| كاشير | `cashier@hallagi.sa` | `Hallagi@123` | البيع، العملاء، الخزينة |
| حلاق | `barber@hallagi.sa` | `Hallagi@123` | «ملخصي» فقط: خدماته ومستحقاته + بيع على نفسه |

عند إنشاء منشأة جديدة من لوحة المنصة يُنشأ معها: الفرع الأول، حساب المالك، الاشتراك،
والخدمات الأساسية — ليتمكن المالك من البيع فورًا بعد الدخول.

## 4. متغيرات البيئة

انسخ `.env.example` (في جذر المشروع) واستخدمه كمرجع:

```bash
# إعدادات قاعدة البيانات
ConnectionStrings__Default="Server=(localdb)\MSSQLLocalDB;Database=Hallagi;Trusted_Connection=True;TrustServerCertificate=True"

# المصادقة (مفتاح قوي 32+ حرفًا إلزاميًا في الإنتاج)
Jwt__Key="REPLACE-WITH-STRONG-32+CHAR-SECRET"
Jwt__Issuer="Hallagi"
Jwt__Audience="Hallagi"
Jwt__ExpiryMinutes="720"

# زرع البيانات التجريبية عند البدء (تطوير/عرض فقط)
Seed__OnStartup="true"

# أصول CORS للواجهة
Cors__AllowedOrigins__0="http://localhost:4200"
```

## 6. تعليمات مهمة قبل الإنتاج

1. **المصادقة:** بدّل `Jwt__Key` بمفتاح قوي (32+ حرفًا) — المفتاح المرفق للتطوير فقط.
2. **كلمات المرور:** احذف حسابات العرض أو غيّر كلماتها؛ لا تستخدم `Hallagi@123`.
3. **HTTPS:** فعّل شهادة TLS واربط `https://your-api` بالواجهة.
4. **قاعدة البيانات:** استخدم SQL Server كامل (أو Azure SQL) مع نسخ احتياطي مجدول.
5. **RLS:** تطبيقنا يطبّق عزل المنشآت في طبقة الخدمات (كل استعلام مُفلتر بـ `organization_id` من التوكن). 
   إذا نقلت لاحقًا إلى Supabase/Postgres، أعد إنشاء هذه السياسات كسياسات RLS مطابقة.
6. **الفوترة الإلكترونية:** الإيصال الحالي غير متوافق مع متطلبات هيئة الزكاة والضريبة (فاتورة) — 
   يحتاج تكاملًا منفصلًا ومتطلبات تنظيمية قبل الاعتماد.

## 7. الميزات المنفذة

**البيع والعمليات:** شاشة بيع لمسية سريعة، إجمالي فوري، عميل اختياري، دفع نقدي/بطاقة،
حفظ بمعاملة ذرية + مفتاح Idempotency يمنع تكرار البيع، شاشة تأكيد، إيصال قابل للطباعة يحفظ السعر وقت البيع.
**وضعان للتشغيل:** بيع بالكاشير (يختار الحلاق) وبيع ذاتي للحلاق (يُسجّل على نفسه تلقائيًا).

**المالية:** خزينة/ورديات لكل فرع، معادلة صريحة للنقدية المتوقعة، حساب الفرق عند الإقفال،
مصروفات منفصلة (درج/بنك)، إلغاء موثق بدل الحذف النهائي، سجل تدقيق.

**إدارة الحلاقين المالية (جديد):**
- سجل مالي لكل حلاق (عمولة، راتب، سلف، تسويات) بقيود دائنة/مدينة قابلة للعكس.
- سلف مع تتبع المتبقي والسداد الجزئي.
- تسليمات نقدية بين الأشخاص مع تأكيد.
- **تسويات مالية**: فترة مالية ← حساب مسودات ← اعتماد وقفل ← دفعات جزئية،
  مع حساب مختلف لكل اتفاق (راتب / عمولة / راتب+عمولة / تأجير كرسي) ولا يُعاد حساب تسوية معتمدة.

**SaaS:** خطط اشتراك (تجريبي/أساسي/احترافي) مع حدود للفروع والمستخدمين والحلاقين،
تسجيل أجهزة POS، فصل الجهاز عن المستخدم والوردية.

**الإدارة:** خدمات وأسعار لكل فرع، حلاقون بأربع طرق تعويض، عملاء مع سجل زيارات، فروع،
مستخدمون وصلاحيات دقيقة قابلة للضبط، تقارير مع تصدير CSV.

**الأمان:** مصادقة JWT حقيقية، أدوار (مالك/مدير فرع/كاشير/حلاق)، فحص صلاحيات مركزي في الخادم،
عزل كامل بين المنشآت والفروع، مفتاح Idempotency يمنع تكرار العمليات المالية.

## 8. الاختبارات

```bash
# اختبارات الوحدات (خادم — تستخدم SQLite داخليًا، لا تلمس قاعدة التطوير)
dotnet test tests/Hallagi.Tests

# اختبارات القبول REST (الخادم يعمل على 5095)
powershell -File scripts/verify-tests.ps1

# اختبارات E2E (Playwright — الخادم + الواجهة يعملان على 4300)
cd hallagi-client
npx playwright test                        # رحلات المستخدم الأساسية
npx playwright test e2e/pages-audit.spec.ts # فتح كل الصفحات بدون أخطاء
```

النتائج المتحققة فعليًا في هذا الإصدار:
- **46 اختبار وحدة ناجح** (عزل المستأجرين، الحسابات المالية، طرق التعويض الأربع،
  قفل التسويات، السلف، منع تكرار القيود، وضع بيع الحلاق، ومنصة المالك).
- **10/10 اختبارات قبول REST**.
- **8/8 اختبارات E2E** لرحلات المستخدم.
- **21/21 صفحة** تُفتح بدون أخطاء (فحص audit).

### ملاحظة تشغيلية
على جهاز المطوّر قد يعمل مشروع Angular آخر على المنفذ 4200. إذا حدث تعارض:
شغّل الواجهة على منفذ بديل وأضفه لأصول CORS في `appsettings`:
```
dotnet run --project src/Hallagi.Api          # http://localhost:5095
npx ng serve --port 4300                       # http://localhost:4300
```
